# NovelWorld

NovelWorld 以 NovelHarness 导出的单本小说 repository 为唯一外部故事来源，支持 JSON/JSONL 目录和十三表 SQLite。世界与人物模拟后，每个通过验收的事件组产生一份故事草稿。一条故事线完整通过验收后，即可从其草稿时间轴生成一个或多个叙述版本。

## 开始使用

在 Linux 或 macOS 上，从 NovelWorld 根目录用 Python 3.11 或更高版本创建虚拟环境并安装依赖。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -B main.py --help
```

在项目根目录创建 `repository/`，将你自己的**单本小说完整导出目录**放入其中，保留上游文件名和目录层级。用 `BOOK_ID` 表示本次选用的书目目录名。`repository/BOOK_ID/` 下包含 `timeline/timeline.json`、各时间节点的任务和状态快照，以及 `roles/`、`objects/`、`locations/`、`worlds/` 中的已有资料。每本书或每个版本单独放一个目录。

输入采用统一的 repository 1.4 格式。人物经历与技能形成过程保存在 `profile`，当前掌握的技能放在人物状态 `current_skills`；通用背景使用 `worlds/background/general.json`，设定使用 `worlds/settings/settings.jsonl`。世界读取这些材料，人物知情仍须独立审核。事件的 `todo`、`required_results` 与 `state_changes` 用于目标验收，生活细节不应仅为扩充素材而写成硬性要求。`participants` 是参考事件的实际参与者，不表示模拟中这些人已经交谈或获知结果。

快照使用 `character_states`、`object_states`、`location_states`、`relationship_states` 四类状态。变化的 `after_values` 必须交齐全部字段：`{"inherit": true}` 保持前态，`null` 只在允许字段表示未知，`[]` 表示明确清空列表。关系以 `add/update/remove` 新增、更新或删除。运行入口将其转换为内部稀疏更新，模型不用重复交付继承占位。环境和使用条件归地点并沿上级地点链读取，人物行动条款不自动成为本人已知事实。

后续节点快照须与前面事件组的参考变化回放一致；实际模拟状态仍由本线行动形成。输入更新后使用新的运行目录；旧运行绑定原输入和执行指纹，不能用新版资料或新版状态解释直接续跑。旧运行、费用和冻结源码保留。

## 每次实验的配置

`configs/example/` 提供两份模板。模拟需要 `simulation.json`，用于选择输入、运行目录和模型预算。生成叙述时才需要 `narrative.json`，用于选择叙述版本、写作要求和该版本的模型预算。Git 只跟踪模板，具体实验的配置在本地管理。

样例按一次模拟树 800 万 token、一次择线及写作版本 200 万 token 分配预算。发送前按请求 UTF-8 大小、输出额度和协议余量保守预留；这不是第三方计费的数学上界，也不保证预算内一定完成。新增独立实验或叙述版本有各自预算，不自动共用一个全项目钱包。已有实验配置不会被样例变更覆盖。

每次实验从项目根目录复制整套模板，使用新的实验编号。下面的命令创建第一套实验配置 `exp-001`。

```bash
cp -R configs/example configs/exp-001
```

编辑 `configs/exp-001/simulation.json`，将 `repository` 中的 `BOOK_ID` 换成实际目录名，再将 `run_directory` 从 `../../runs/example` 改为 `../../runs/exp-001`。运行目录须位于输入目录之外且尚未创建。`repository` 可以指向某本书的完整导出目录或已有 SQLite 文件。所有相对路径都以配置文件所在目录为基准。

**运行模拟**。示例模型从环境变量 `DEEPSEEK_API_KEY` 读取密钥。设置后，用本次实验的配置启动。两份配置均可通过 `model_config_path` 选用各自的[模型配置](model/config.example.json)。

```bash
.venv/bin/python -B main.py run --config configs/exp-001/simulation.json
```

若要先离线检查输入，可先用 `init` 初始化，再用 `status` 查看。准备好模型后用 `resume` 继续该运行。

```bash
.venv/bin/python -B main.py init --config configs/exp-001/simulation.json
.venv/bin/python -B main.py status --run-directory runs/exp-001
.venv/bin/python -B main.py resume --run-directory runs/exp-001
```

在 `run`、`resume`、`narrate` 或 `summarize` 后加 `--progress`，终端会即时显示任务开始与完成、
模型请求及回执用量；模拟还显示节点、事件组、轮次、原子提交和组草稿保存。
进度写入标准错误，最终状态 JSON 保留在标准输出。每轮提交和每组验收后刷新已保存内容的文件投影：
`world_state.json`、`memories/`、`simulation/events/*/actions.jsonl`、`story_progress.md`，
以及已验收组的 `simulation/groups/*/draft.json` 和 `story.md`。未提交候选不会进入行动文件，未验收组不生成正式草稿。

**生成叙述**。完整模拟结束后，可以按本次实验的叙述配置生成正文。同一份模拟需要比较不同写法时，可另存一份叙述配置并设置新的 `version_id`。

```bash
.venv/bin/python -B main.py narrate --run-directory runs/exp-001 --config configs/exp-001/narrative.json
```

`retry --help` 说明如何从指定事件组的检查点创建独立尝试。运行目录中的 `run.sqlite3` 保存状态与进度，`story_progress.md` 展示已提交的模拟材料，叙述版本放在 `narratives/<版本编号>/`。

## 模拟中探索不同可能

配置只设容量和并发。默认允许整棵树最多保留四条最终时间轴，示例设置相同、同时运行两个分支。若要全程单线，设 `max_timelines` 为 1。新配置不接受预先列出节点和分支名称的 `branch_plan`。

```json
{
  "max_timelines": 4,
  "branch_parallelism": 2
}
```

模拟抵达一个时间节点的首组入口时，如果还有探索额度，世界依据当前状态和已发生的行动判断是否分叉。它可以继续原线，也可以提出不同的、有现场依据的行动机会。每条子线继承分叉点的已提交世界、人物记忆和草稿，独立继续，还可在更晚的节点分叉。各线不合并。一个分支的探索方向只交给该分支的世界调度，人物自己决定回应。运行预算在子线间分配，共同历史只模拟一次。

使用前面的 `run`、`resume`、`status`，目录均指向树根。`max_timelines` 是上限，最终可能只有一条；`concurrency` 控制整棵树同时在途的模拟请求数。要从已有的兼容节点入口开一个新实验，在新配置中设同一 repository、不同运行目录及探索容量，再执行以下命令。将 TN_2 替换成该运行已经保存入口和费用记录的实际节点。

```bash
.venv/bin/python -B main.py fork --run-directory runs/exp-001 --node TN_2 --config configs/exp-002/simulation.json
.venv/bin/python -B main.py resume --run-directory runs/exp-002
```

同一组的事件共享批前状态并共同验收。`story_timeline.json` 按节点和组索引，每个通过验收的组对应一份 `simulation/groups/<组编号>/draft.json` 和可读的 `story.md`。组未通过时可阅读 `story_progress.md` 的已提交经过，此时该组没有正式草稿。事件级行动记录保留在 `simulation/events/` 供诊断。

人物首次初始化和组内记忆归档可在 `concurrency` 上限内并行，整批成功后统一保存；模型请求在本次运行内复用 HTTP 连接。记忆审核指出具体人物的问题时，只重写相关人物的候选，再对全体候选一起复核；无法定位的问题仍交全员返修。人物记忆优先记录本次新增的见闻、互动、尝试结果与认识变化，没有新印象时可不新增记忆。故事中的实际动作、言语和各人的体验仍保留在正式材料中。

起点档案按人物处理，每人将完整合法静态描述和完整起点状态作为一份资料，允许两者联合支持认识；身体状况是否恢复等状态含义不能作为技术字段丢弃。模型直接生成完整的本人起点认识，非空时再说明各项知情依据；程序绑定本人来源及引文，不逐字段询问。多项认识仍逐项审读，不按短句截掉材料。每个人的生成上下文只包含本人资料及本人的返修意见，登记编号本身不等于人物知道的内容。 起点返修只重写审核明确指出的人物，未受影响的完整候选原样保留；定位不明确时不擅自跳过生成。整批仍须通过来源校验和完整审核覆盖后才能交付。

世界、人物和叙述任务统一由 `agents/NovelRestoreSupervisorAgent.py` 的工程总 agent 分发。真实模型使用 AutoGen `AssistantAgent` 与 `FunctionTool` 完成完整业务任务：一次人物初始化、连贯行为选择、整批世界裁定、记忆更新或独立审核，一次提交对应的完整候选。模型生成语义判断和丰富正文，SDK 定义接口并校验参数。程序绑定人物、行动、来源引文和新章节身份，分配写作篇幅；人物的需要与紧迫感用自然语言表达，由人物自行选择目的、连贯行为和预期停点，不计算需求效用、不按比例预抽行为类型。正常任务不额外调用总 agent 模型。

世界按稳定的目标身份分别记录核心事件、关键状态与承接缺口。中间条件和替代路径只是可调整的规划假设，不能增添必须照演的剧情。机会记录明确缺口、现场依据、谁可感知、本人动机、可能回应、预期贡献及风险；真实回应到来后再记录实际改善、退步、无变化、探索所得和下一次调整。一项目标改善不能清空其他目标的停滞。事件已经发生而状态仍不足时继续解决状态缺口，保留已发生历史。

人物在同一次决策中选择一段连贯行为，说明本人目的、必要言语、简短理由和预期停点。无须重新选择的移动、取物、操作及伴随言语可以合并；重要新信息、实质阻碍或他人的自主回应仍是停点。世界保存实际顺序、完成范围、未发生部分、耗时及各人的体验，同批行为只结算到共同时间窗。段末获得的信息不能倒填为段首的选择依据。人物只更新实际变化的认识、需要和当前打算，未变化内容沿用。合法拒绝、误判或冒险不因不利于目标被重选。行动、主观更新、共同时间和逐项目标进度原子保存。

当前互动可由本批进展反馈直接提出下一位实际获得体验的人物，经独立审核后与本批一起提交。下一批由该人物自主回应，使用前批已审的最终个人体验，省去重复机会调度与重复感知生成；同时行动仍共享前态，先后回应使用已提交的新前态。有新阻碍、需换场景、接续条件不足或达到停滞阈值时回到正常调度。普通连贯过程合并，关键选择、必要对白、因果和重要心理变化完整保留；内容量随实际复杂程度变化，不靠强行截短、降低验收要求或删去必要经历提速。

回想是人物行为任务中的可选 `personal_recall` 工具，没有查询就直接交付行为。程序只查本线本人的已提交历史；零命中不补入旧经历。没有提取作用时原样返回批准来源，有作用时先加工并独立审核，再返回同一人物任务。缓存实际交付以支持恢复，原始命中不会泄漏给本人。

示例配置的 `plan_candidates=3`（候选上限，不要求凑数）、`max_personal_lookups=2`、`goal_stagnation_batches=3`、`goal_progress_window=3`、`max_blocked_replans=2` 是可评估的工程初值，不宣称最优。旧的行为比例和需求评分参数不属于当前方法。`plan_steps` 和 `summary_interval` 仅用于读取历史配置，不控制新运行。世界在正常调度中交付机会依据和预期，随后依据实际行动反馈调整；没有独立短程试演流程。

模型传输使用官方 OpenAI Python SDK 的 Chat Completions 接口及 AutoGen 消息转换，要求所配置的兼容接口支持原生工具调用。SDK 隐藏重试关闭；每次实际请求、重试和完整回执均计入同一账本，未知送达不会自动重发。合法工具交付兼容接口的 `stop` 完成标记；可选推理附加信息的类型异常不影响有效参数，原始回执仍完整保存。

模型交付语义判断和故事内容；选择行动者、证据来源、受影响旁观者、记忆关联及叙述视角仍属语义工作。程序固定已知的任务身份、接收者、替换位置、原始证据值、来源类别和存储结构。原生工具参数承载这些语义结果，不要求模型生成文件、执行补丁或重新抄写已有记录。

模型任务必须有明确的内容契约和装配函数，或显式声明为纯语义交付；未声明的内部记录不能直接成为模型接口。调度和进度评估按程序固定的事件顺序交付，程序绑定事件键；重规划的最近行动、共同锚点和停点不重复抄写。新感知对象只交付描述、实际对应及依据，程序生成局部编号和两侧对应表。认知处理阶段由任务及已生效作用绑定。记忆、知情和叙述审核交付具体问题，程序计算汇总结论；缺失问题列表不能当作“没有问题”。

个人体验返修由程序定位被指出人物的已有交付，一次请求只接收这些位置的文字与对象描述；对象编号、行动归属和未涉及人物的内容沿用原值。返修提示不再同时要求重新裁定整批世界。行动前感知及人物返修提示按程序确定的接收者顺序绑定；知情审核逐人交付问题，程序装配覆盖名单和汇总结果；正文按已选目标顺序绑定片段身份。这些固定映射在业务装配层完成，通用 JSON 工具不猜测跨人物的归属。修正后的完整候选仍须通过原有程序校验与独立审核，不能把结构正确当作知情正确。

接口未返回有效用量时，费用统计保留 `tokens`（实报）和 `unreported_usage_calls`（未知笔数），另列 `reserved_tokens`（未知用量的预算预留）、`budget_tokens`（实报加预留）以及逐笔预留明细。文本请求按已存请求的 UTF-8 字节数加 4096 输入余量，加请求中指定的输出上限；未指定输出上限时预留 131072 输出 token。有效的部分用量只会提高预留。该规则是保守预算策略，不是第三方接口真实计费的严格上界。预留不修改原始请求或回执，收到有效用量后由实报替代；请求记录损坏、无法计算预留或预算已耗尽时仍停止。明确未送达的连接失败不预留费用。

预算判断及分支分配使用实报加预留，叙述也承担择线阶段的预留。普通 `resume` 不自动重发未知请求。明确接受该笔请求可能重复计费时，可执行 `resume --run-directory <运行目录> --retry-unknown`：保留原运行的有效调度、审核、感知及人物任务，只重试未完成任务；旧未知账目和预留保持不变，新请求另行记账。该授权只覆盖启动时已有的未知请求，新发生的未知送达仍暂停；预算、源码、提示、输入和任务依赖检查均保留。

`retry --preserve-progress` 则用于隔离的新尝试，继承已提交行动与全部费用，但重新准备未提交轮次。代码改变后不能直接续跑已绑定旧执行指纹的运行，应保留旧现场并创建独立尝试。费用恢复不代表未提交的故事已经发生，也不改变行动的原子提交规则。

JSON 读取、修复、参数归一和 Schema 精简集中在 `tools/`，由程序直接调用 Python `json`、JSON5、`json-repair` 和 Pydantic；这些本地工具不发送模型请求。完整代码块、字符串转义、重复编码的 JSON 文本、完整值后多出的闭括号，以及对象或字符串形式的单层 `arguments` 包装，均在统一入口恢复。单引号和内部尾逗号使用 JSON5 解析器；缺少已打开容器的闭括号时使用 `json-repair`，另以原文本仅补必要闭括号后的完整解析核对，防止修复库补值、改正文或覆盖重复键。完整内容缺少唯一固定 `result` 外层、或字段落在外层时，仅在完整契约校验通过后装配。Pydantic 的缺失/多余字段路径可以定位同名字段的唯一祖先归属；多来源、多项数组及跨独立对象的归属不猜测。正文字符串不递归解码，多对象、重复键、截断正文或缺失值不被丢弃或补写，外部 repository 的固定输入契约不变。

交付中未声明的空字符串、空容器或 null 由程序剥离，即使同时缺少语义内容，也先完成这项确定性归一。余下错误按归一后的真实位置反馈，候选只有通过完整校验才能交付；原始回执保留。有内容的未知字段、缺失判断不会被删除或用默认值变成审核通过。

故障按实际捕获点区分语法、结构、业务、查询、调用协议、网络和执行保护，并记录处理路径。无歧义的结构归一和字段归位仅在本地执行，不设置模型字段搬移任务。缺失的语义字段、错误标量及有明确参数位置的业务错误，可用 `amend_result` 一次交付所列项目的新语义值；位置与 `add/replace` 操作由程序绑定，再用 `jsonpatch` / `jsonpointer` 在候选副本上合并。模型不写补丁；原资料和完整候选保存在任务记录，返修发送相关资料、待修项目及已查依据。其余内容保持不变，完整校验和独立审核继续执行。无法确定内容归属时返回有完整依据的原语义任务，程序不猜测跨人物或行动的事实归属。总 agent 沿用有限升级和原预算，网络及来源、权限、送达保护不交模型处理；未知故障保留现场，不自动扩大权限。每次恢复都保存原候选、回执和处理状态，已完成步骤可重放。

局部返修仅携带未解决项目的类型与约束，不重复发送整套交付结构。多个项目中已有有效修正时，程序保存合并后的候选，下一次只补剩余错误；新补对象仍缺少内容时，继续定位到其缺失字段。这些候选尚未通过完整验收，不会部分提交为故事事实；中断恢复沿用同一份待修候选。

世界按任务准备发送视图：当前候选与实际经过保留原文，历史感知附件通过行动编号补查；感知只默认装入本次接收者的主观资料，近期体验、显式引用及纠正链保留。目标证据仅在版本、前后时点、路径和值均相同时共用原值引用，完整档案仍在运行库。局部目标与现场依据返修只发送相关项目及必要现场，个人体验返修固定归属并保留客观裁定。目标的原状态证据在批前、批后均未变化时，模型可明确判断语义未变并说明理由；程序装配旧依据、清除旧贡献，独立审核仍逐项检查全部候选，不据格式相同自动判定目标完成。

原生工具参数可能存在格式偏差，由本地程序先解析与归一，再对剩余内容问题进行有限语义补答；这一恢复流程不依赖接口提供严格生成模式。程序负责文件路径、序列化、写盘和数据库提交。无法确定含义或完整读取的故事内容不能凭空补成成功结果，必要的语义重交仍受原预算和审核约束。

其余工具错误先在 `format_repairs` 范围内反馈原任务；仍未交付时，总 agent 以独立会话接管，使用原任务工具与权限诊断修复。`supervisor_turns` 限制每次接管的模型请求数（默认 2，设为 0 可关闭模型升级），所有调用仍计入总预算。外层语义返修用尽后也允许一次总 agent 候选修复，随后仍由原审核者独立验收；不能自行批准或提交故事事实，恢复失败不会递归创建管理者。审核分类与工具契约按具体任务约束，填错分类进入局部纠正。

每个完整任务有独立会话，人物只接收本人已批准资料。起点档案逐人生成和独立审核，同批结果完成后统一保存；未出生者的空档案由程序处理。世界任务按参与人物、引用、实际条件与状态变化准备资料，保留全局关系、公共状态和限制；范围外资料可通过世界只读工具补查。没有查询能力或无法确定范围时保留完整状态。审核候选的引用也参与准备证据，不能只沿用生成方所选范围。

进度判断读取已完成内容审核的行动实际后果、个人体验和心理变化，避免重复读取存储用的记忆、输入与审核附件。当前待审候选仍完整提供。相同或近似的状态快照按一份基准与程序生成的 JSON Patch 差异表达，实际状态与目标参考明确区分。完整记录、对白、体验和草稿不被截断或改写；旧记录可按身份回读，未展示不等于不存在。

目标、事件完成及组验收的状态证据只由模型选择路径；程序从本次任务的完整实际前态或后态绑定原值，不从目标参考或展示投影取值。缺失路径按候选位置集中反馈；历史格式带回的 `value` 仅在这一输入类型中被实际值替换，不要求模型重抄已有记录。内部证据、来源校验和独立语义审核保持完整。

认知处理只交付受作用影响的档案、心理、体验或回想变化；未列内容由程序完整沿用，体验的来源类别由程序绑定。抑制体验或回想须显式表达并具有相应认知作用依据。装配后的完整个人输入仍经过原来源校验与独立知情审核，不能靠漏写内容删除已获得的资料。

原生工具定义保留 Pydantic 的 `$defs`/`$ref` 共享结构，不反复展开同一种引用模型；必需字段、合法取值、额外字段限制与完整业务校验保持。模型端需支持这些标准 JSON Schema 引用。返回的 `reasoning_content` 在工具续答时沿用原生字段，不再被 AutoGen 默认转换为普通 assistant 正文，也不把它当作故事资料。

本人已有心理按确切来源承接；没有新的认知作用时由程序沿用，不额外生成一份同义内容。新的记忆一次联合生成，避免分别按类别重述相同经过。人物仍可以误解、犹疑或改变判断，主观内容不能仅因与客观事实不同就被删除。资料未交代环境细节不代表人物失明、失聪或失忆，感知障碍必须有独立的实际依据。

任务及原始接口回执先保存，行动、状态变化、人物记忆和进度仍整批原子提交。恢复校验源码、提示、工具契约与任务输入指纹，旧实验继续使用其冻结版本，不能跨协议续跑。失败后的批次禁止新请求，已发送请求继续收妥回执；拒收的候选不写成客观故事事实。已结束的未完成故事线恢复时只重建导出，继续尝试使用独立运行。

真实模型的任务规则来自 `prompts/NovelRestoreTaskPrompt.md`；工程恢复额外使用 `prompts/NovelRestoreSupervisorPrompt.md`。正常交付返修和总 agent 恢复均可清除被后续候选替代的旧交付，保留原任务资料、全部已读查询依据与最后候选及其工具错误；仅在确实变小时使用该视图。请求超限时也使用相同规则，必要资料自身仍超限则保留现场。查询额度用尽后关闭查询工具，允许依据已读资料提交；总 agent 的最后一轮也保留给交付。阶段、次数、查询关闭状态与 SDK 会话随任务保存。显式离线记录夹具只用于回归测试，不触发模型恢复。离线测试不能证明真实接口速度、费用或文学质量。`max_calls`、`max_tokens`、`max_request_chars` 等运行预算仍适用；工具定义计入实际请求长度。

运行配置显式设置 `max_calls: null` 和 `max_tokens: null` 可取消调用次数和 token 预算上限；真实模型配置中的 `max_calls` 也须设为 `null`，否则仍采用较小的有效上限。费用账本继续累计，审核、未知送达保护和方法规定的分支停止条件不变。省略执行配置的 `max_calls` 不等同于明确选择无限额。

HTTP 请求日志记录工具定义、初始材料、后续消息及推理字段的字符量，实际 token 仍以接口回执和费用账本为准。字符量与离线分词器估算不作为计费 token。上下文缩小是否导致额外查询、返修或内容质量变化，需要在同等推进量的实验中验证。

`max_tokens` 是当前预算范围的已结算用量停止阈值：模拟预算分配给子线，择线与所选叙述版本合计另用该版本预算。它不是模拟到成稿的统一硬上限；尚未预留本次及在途请求的输入、输出用量，因此回执到达时可能越过阈值。示例未设置 token 限额，不能仅凭 `max_calls` 推断完整实验的 token 上限。预算耗尽后的暂停不代表已经完成作品。

数据库是提交结果的依据。世界文件、人物文件及可读日志导出失败时，记录 `status.deferred_exports`，模拟可继续；恢复时从数据库重建，不重跑行动、不覆盖人工改动。叙述导出失败显示 `export_error` 且 `published=false`。个人摘要是可选检索辅助；默认不生成，不阻塞组完成、整线完成和叙述。需要时运行 `python main.py summarize --run-directory RUN_DIR --group-id GROUP_ID`，使用该运行的预算和执行绑定。失败记录在独立辅助任务中，返回 `summary_failures`；可单独恢复，不改冻结草稿。恢复复用已交付结果，耗尽全部返修的否决不会自动重买请求或变成批准。数据库、未知送达、预算和来源一致性问题仍保留停止保护。

模拟同时追求充分素材与有效推进：动作、完整言语、个人体验及有意义失败按实际发生保留，但字数与记忆条数不替代目标进展。人物自主性、同批共享前态、节点分叉、一组一稿及写作只读冻结草稿的约束不变。

记忆检索直接使用 Jieba 搜索分词、标准中英停用词数据和 BM25 排序，不增加模型或 embedding 请求。人物检索仅限本人实际已获知的记录；明确的主题线索须来自本次问题，没有匹配时不补入无关的近期记录。重要性和时点用于同分排序，纠正关系保留完整可见链。词法检索不保证识别所有隐含同义表达。

从树根执行 `narrate`。每个叙述版本只选一条完整、已验收的故事线。择线、章节规划、正文和事实审核均以该阶段允许的正式组草稿为故事资料；版本配置用于篇幅、风格、视角等表达要求。所选线的正文位于其 `narratives/<版本编号>/`。用树根的 `status --version`、`resume --version` 查看或继续该版本。

规划审核在原有一次交付中定位全局、章节或关联问题。章节问题只重做受影响且来源相应的布局，关联问题可保留已有布局；全局问题或无法定位时重做全书规划。修复后仍检查完整计划及来源覆盖。同一修订过程可复用候选与全部依据完全相同的审核回执；相同否决也不会因为重复提交变成批准。重启后仍按持久任务和输入指纹恢复，未重建的跨次审读索引可能导致再次审核。

## 代码和数据边界

| 位置 | 职责 |
| --- | --- |
| `main.py`、`workflows/` | 命令入口、执行配置绑定、模拟及叙述生命周期；组织同批裁定、主观更新、进展审核和原子提交 |
| `agents/` | 工程总 agent 的分发与恢复，以及世界、人物、叙述者三类角色的任务 |
| `execution/` | 单任务 SDK 工具执行、显式契约路由、任务回执及独立审核；离线脚本独立实现 |
| `inputs/` | JSON/JSONL 与 SQLite 只读输入适配、公开状态契约、引用校验、回放和历史查询 |
| `simulation/` | 人物与世界任务的语义交付及程序装配、任务与返修上下文、体验、主观记忆、知情边界和运行状态规则 |
| `narration/` | 冻结草稿的写作上下文与交付装配，以及世界角色在叙述阶段的委托、计划审核和正文复核；不是新增智能体 |
| `common/` | 共享配置与数据模型、运行信号、编号及序列化 |
| `model/` | HTTP 请求、连接、原始回执及模型配置样例 |
| `tools/` | 本地确定性工具：严格 JSON 读取、模型 JSON 格式修复、参数归一与 Pydantic 校验、Schema 精简；不调用模型或提交故事状态 |
| `storage/` | 运行库、批次与检查点事务、恢复、费用账本、叙述版本，以及已保存结果的文件导出与人工修改保护 |
| `prompts/` | 按完整任务划分的语义规则与交付边界 |

`agents/` 定义各角色做什么，`workflows/` 决定流程何时进入下一步，`execution/` 处理一次模型任务的调用、返修和审核交接，`model/` 负责接口传输。`tools/` 提供由程序直接执行、没有故事领域状态的确定性工具；状态回放、人物知情、记忆和草稿生成仍归其业务模块，不把所有非模型代码都集中到工具目录。

| 本地资料或支持目录 | 职责 |
| --- | --- |
| `configs/` | 配置模板及各次实验的参数、冻结执行版本；历史版本用于复现 |
| `repository/` | 唯一外部故事来源，运行时只读 |
| `runs/` | 各次实验的数据库、检查点、原始回执、费用账本及故事产物 |
| `tests/` | 当前有效的离线回归、夹具和验收结果；已退役机制的无效测试不混入回归集 |
| `docs/` | 本地技术路线、开发设计与核对说明，不进入运行提示 |
| `reports/` | 本地输入适配、备份和检查记录，不作为额外故事输入 |
| `LICENSES/` | 项目及复用代码的许可正文 |
| `.venv/`、`.git/` | Python 依赖环境与版本管理元数据 |

源码与提示的所有子目录均纳入执行指纹。目录调整后不保留旧路径转发模块；旧运行继续使用其冻结版本，避免在恢复中混入新实现。`repository/` 专放只读小说输入，`configs/` 保存本地实验配置，`runs/` 保存运行结果，均不与源码目录混用。共享检查点由存储接口整批提交，角色和工作流不直接写库。

叙述配置的 `version_id` 使用 1 至 64 个英文、数字、点、短横或下划线字符，以字母或数字开头。`requirements` 可以省略，或填由标点分隔的表达选项，如“白描，倒叙”。`version` 可明确指定 `person`（如“第三人称”）、`pov`（如“人物限知”）、`style`（如“克制”）、`pacing`（如“紧凑”）、`reveal_policy`（如“逐步揭示”）、媒介及篇幅。各字段接受固定选项，错误值在请求模型前拒绝。

目录输入在内存中建立索引。初始化校验资产引用、时间节点、事件组与相邻快照连续性，遇到上游的 `.incomplete.json` 标记会拒绝运行。模拟只读这份资料，运行进度写在独立的 `run.sqlite3`。继续同一运行时会核对输入指纹，修改原书资料后需新建运行。

两种输入共用事件规范化：可选的 `time`、参与人的 `original_goal` 省略时与 `null` 等价；没有地点引用时，地点名称的空数组与 `null` 等价。这些转换仅在内存中进行。必需字段、身份、引用和实际内容冲突仍须在输入中解决，程序不会补写故事事实。结构错误报告对应文件或数据库记录及字段位置；模型配置中的非法接口地址和数值在创建运行、读取密钥及登记请求之前拒绝。

新运行使用格式 22（方法 1.41）。正式组草稿按行动时点保留人物决策前的认识，以及行动后记录的体验和心理。首次模拟时，世界根据故事起点资料提取各人当时有依据知道的内容，并经独立审核。人物只接收核准的本人资料，完整档案留在世界侧。初始化审核计入本次实验的调用预算。此后人物在行为选择任务中按需调用工具检索本线自己的记忆。命中并实际形成的回想按当时的主观体验写入行动材料。格式 17 至 21 的组草稿按原结构只读查看，历史资料保持当时记录的范围。旧格式运行保持原状，可查看已有状态和文件；需要继续旧实验时使用原执行版本。

审核复用绑定确切候选、来源、接收人、规则和可查询资料范围；依赖不明时完整重审。同批记忆局部返修保留未改人物的批准，另存覆盖记录；新增与受影响内容独立审读。整组验收读取累计目标证据、当前状态及必要承接材料，需要时回查原始行动，不默认重传全部经过。
